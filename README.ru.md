# pingtun

[English](README.md) · [Установка](INSTALL.ru.md) · [Релиз 0.4.1](https://github.com/bug0000/pingtun/releases/tag/v0.4.1)

**pingtun 0.4.1** — шифрованный IPv4 VPN поверх ICMP Echo Request/Reply.
Один Linux-бинарник работает сервером или консольным клиентом. Android-клиент
использует системный VPN и ICMP datagram sockets, без root и Google Play
Services. Обмен ключами, шифрование и защиту от повторов обеспечивает
WireGuard-go. Собственный транспорт написан на Go; код Hans не используется.

## Скачать

В [GitHub Release](https://github.com/bug0000/pingtun/releases/tag/v0.4.1) доступны
архивы Linux amd64/arm64, подписанный APK для Android 10+, SHA256SUMS и лицензии.
Android 0.4.1 (versionCode 3): новый интерфейс, адаптивная иконка и раздел
«О приложении». Подпись сохранена — APK устанавливается поверх прошлой версии. Закрытый ключ подписи,
VPN-профили и рабочие конфигурации не публикуются. Интерфейс Android пока русский.

## Возможности и границы

- Адаптивный v2: короткие служебные пакеты в простое, общий ограничитель темпа
  и окно запросов, ограниченные очереди, логические каналы, восстановление
  после перезапуска сервера и статистика без ключей.
- Один шифрованный клиент на экземпляр сервера; отдельные ключи для каждого.
- Необязательная [веб‑админка](admin/README.ru.md) создаёт и управляет
  отдельными экземплярами для Android и Linux клиентов.
- `init` создаёт v2: стабильные ID, MTU 1280 / внешний MTU 1440, два канала,
  предел 250 пакетов/с и окно до 32 запросов. `init --legacy` создаёт v1.
  Существующие конфиги и профили сохраняют свой протокол и ключи.
- `mobile-init` создаёт отдельный профиль телефона. Android хранит его через
  Keystore AES-GCM и удерживает TUN при восстановлении транспорта.
- `probe`/`probe-server` измеряют аутентифицированный ICMP отдельно от VPN.
- Linux-процесс создаёт только свой TUN. При ручной установке маршруты,
  forwarding и NAT настраивает администратор; см. [инструкцию](INSTALL.ru.md).

Поддерживается **только IPv4**. Android перехватывает и блокирует IPv6.
Логические каналы используют один путь и не означают физическую агрегацию.
Физической агрегации, FEC, Windows, нескольких клиентов на экземпляр сервера и
автоматического переключения всей сети нет. ICMP может блокироваться или
ограничиваться. Внешний аудит безопасности не проводился; см. [SECURITY.md](SECURITY.md).

## Начало работы

```sh
pingtun version
pingtun init --server 203.0.113.10 --dir configs
pingtun check --config configs/server.json
# Отдельная идентичность телефона:
pingtun mobile-init --server 203.0.113.10 --dir configs-phone --name Phone --address 10.203.0.2/30
```

Замените пример адреса и выберите свободную частную подсеть. Каталоги создаются
с правами 0700, файлы с ключами — 0600. Существующие каталоги не перезаписываются.
Для ограниченной systemd-службы устанавливайте конфиги с владельцем root.
Не публикуйте их и не переносите ключи шлюза на телефон. Полная настройка сервера,
Linux и Android описана в [INSTALL.ru.md](INSTALL.ru.md) и [android/README.md](android/README.md).

## Сборка и проверки

Linux, Go 1.27.2:

```sh
go test -race ./...
go vet ./...
go build -trimpath -buildvcs=false -o bin/pingtun ./cmd/pingtun
```

CI включает fuzzing декодеров, проверку зависимостей, настоящий WireGuard и
изолированный Linux-стенд с NAT, потерями/перестановкой, проверкой файлов,
обрывом связи и перезапуском сервера. Datagram-клиент испытывается без
CAP_NET_RAW. Android проверяется в эмуляторе Android 15: запуск, ICMP от UID
приложения и защищённое хранение профиля. Пользователь подтвердил первое
подключение и открытие сайтов через LTE на физическом Android-устройстве без root.
Это один телефон и одна сеть; сон, смена сети, IPv6 bypass, системная блокировка
без VPN и длительная работа на телефоне ещё требуют проверки.
